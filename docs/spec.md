## Full product requirements

| Requirement | Required end state |
| --- | --- |
| Organization setup | A short guided flow creates the organization's actual isolated assistant and reports real readiness or an actionable recoverable failure. |
| Installation and hosting | The service owns provisioning, persistent state, upgrades, backup/recovery and exact resource retirement. Customers do not operate a Linux server. |
| Configuration | Conversation produces a typed intent and reviewed redacted diff, validated against the actual pinned runtime/plugin schema. Persisted and applied states remain distinct. |
| Focused catalogue | Support a deliberate provider/channel subset, beginning with web chat and a proposed single provider binding; unavailable choices remain explicit. |
| Notion | Connect the intended remote Notion MCP through organization-owned consent, scopes, credential lifecycle and revocation. No existing platform credential is inherited. |
| Memory | Retain org-owned sources/provenance separately from derived indexes, with review, retention and deletion behavior. Memory text cannot grant execution authority. |
| Self-building | Agents can propose organization workspace artifacts and changes in bounded sandboxes, expose diffs/evidence and request activation through the deployment owner. |
| Dashboard | Present configuration, runtime/version, conversations, connector/memory health and lifecycle operations with honest loading/error/unavailable/recovery states. |
| Isolation | Verify real separation of organizations' identities, state, credentials, workspaces, connections, streams and backups, including adversarial substitutions. |

The [architecture proposal](proposals/managed-service-architecture.md) records
the inspected immutable OpenClaw contracts and proposed implementation owners.
Its operational policies and provider capabilities have not been activated or
qualified through live deployment.

## Initial source milestone

The first source milestone implements original pure control-plane data and
transitions, plus a browser-local preview over that contract. Records retain
organization/instance ownership, revisions/generations and operation review
state. Typed plans are data; no module import starts a process or calls a service.
The UI can prepare, review, save/import/export actual records and display their
recorded status. It must keep the absence of a hosted connection visible.

This source is deliberately traceable to the full managed workflow. It is not
a local exporter substituted for the hosted product, nor a claim that authored
or imported observations prove real resources exist. Client validation and
confirmation are not authentication or server-side access enforcement.

## Acceptance and remaining gates

Source and static validation cannot establish browser/device behavior, actual
organization isolation, provider execution, hosting or a running assistant.
Author meaningful domain cases without running them until their own execution
scope is approved. No installation, hosted account, DB migration, role grant,
credential use, channel/model call or payment is implied by this source step.

Final managed-service acceptance needs at least two actual isolated customer
organizations, authenticated lifecycle/configuration/chat flows, scoped Notion
operations and revocation, memory retention/deletion, reviewed self-building,
failed-provision recovery, lost-ack reconciliation, pause/resume, upgrades,
backup/restore and exact deletion. Full product and portfolio completion remain
unproven until those outcomes are verified on the selected real infrastructure.
