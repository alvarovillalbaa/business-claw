## Configuration schema and validation

- `config.schema {}` returns `schema`, `uiHints`, `version`, `generatedAt`; `config.schema.lookup {path}` returns a shallow node, immediate `children`, optional hints and `reloadKind: restart|hot|none`. Lookup paths are bounded to 1,024 characters. These are closed request shapes. [Protocol definitions](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/packages/gateway-protocol/src/schema/config.ts#L14-L60), [response definitions](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/packages/gateway-protocol/src/schema/config.ts#L347-L377).
- The authoritative root is `z.strictObject(OpenClawSchemaShape)` with additional semantic refinements. The public JSON Schema is generated as draft-07 input schema with `unrepresentable: "any"`; `$schema` is hidden from the public form, while channel/plugin configuration is extended from runtime metadata. Therefore a JSON Schema snapshot alone is not a replacement for upstream semantic/plugin validation. [Root validator](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/config/zod-schema.ts#L1-L47), [schema generation](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/config/schema-base.ts#L79-L141), [runtime registry selection](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/config/runtime-schema.ts#L12-L44).
- The running Gateway builds schema from its active configuration and exact plugin manifest registry. A release version alone cannot identify every enabled schema. Proposed adapter preparation must retain installation/release identity, selected plugin versions and a stable schema-content fingerprint; `generatedAt` is observation metadata, not a stable schema identity. This fingerprinting is an integration recommendation, not an upstream response field.
- Gateway submissions normalize model references, validate raw authored values and validate the resulting configuration with the write snapshot's plugin metadata. Validation errors use `INVALID_REQUEST`, with complete `details.issues` and a bounded message. Full replacement restores redacted values and projects edits back onto authored source. [Submission gate](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/config-submission-validation.ts#L33-L67), [replacement preparation](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/config.ts#L430-L478).
- No dry-run `config.validate` method is defined in the inspected `configHandlers`. Do not invent that RPC or perform a write to simulate preview validation. The upstream CLI documents `openclaw config validate`; qualifying an approved isolated preflight against the selected runtime/plugins remains future work. Invalid startup configuration refuses boot; an invalid hot reload keeps the accepted runtime. [Handlers](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/config.ts#L774-L1122), [validation behavior](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/docs/gateway/configuration.md#L79-L124), [CLI validation guidance](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/docs/gateway/configuration/hot-reload.md#L73-L85).

## Read and write receipts

`config.get {}` exposes three distinct opaque revision tokens. [Response construction](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/config-get-response.ts#L20-L38):

| Field | Meaning | Adapter treatment |
| --- | --- | --- |
| `hash` | Projected raw persisted-file hash | Echo as `baseHash` for the exact target's write concurrency guard. |
| `configRevisionHash` | Projected source-configuration revision; null when invalid | Compare only with `appliedConfigHash`, not the raw-file token. |
| `appliedConfigHash` | Projected currently applied source revision, or null | Equality supports application observation; missing is unavailable and mismatch is unapplied. Neither proves provider/chat readiness. |

Projection uses a durable per-installation HMAC key with distinct raw/resolved domains. Treat the public values as opaque strings: do not recompute them from redacted JSON, parse a presumed digest format, compare between installations, or substitute the portable workspace revision. [Revision projector](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/config-revision-token.ts#L25-L135).

| Method | Exact request and important behavior |
| --- | --- |
| `config.set` | `{raw, baseHash?}`; full replacement, persistence-only acknowledgment. It rejects removal of existing agent entries; intentional agent deletion uses the dedicated lifecycle method. |
| `config.apply` | `{raw, baseHash?, sessionKey?, deliveryContext?, note?, restartDelayMs?}`; intentional full replacement. |
| `config.patch` | Same apply fields plus `replacePaths?: string[]` (maximum 256); `raw` must parse as a JSON5 object. Object fields merge, null deletes, stable-ID object arrays merge by ID. Destructive array changes require the exact array paths in `replacePaths`; parent/wildcard paths do not authorize descendants. |

Sources: [closed wire shapes](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/packages/gateway-protocol/src/schema/config.ts#L27-L54), [set handler](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/config.ts#L846-L905), [patch semantics](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/docs/gateway/configuration/config-rpc.md#L100-L115).

The general rule requires `baseHash` after a config file exists. The handler has a narrow hashless leaf-write exception for `ui.prefs`; Business Claw setup should still require the observed token. The early check is followed by lock-time CAS during replacement, so a race may still reject the write. Re-read and review against the new snapshot rather than replaying old intent. [Guard](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/config.ts#L99-L135), [preference exception](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/config.ts#L741-L755), [lock-time CAS](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/config-write-flow.ts#L173-L205).

For hot-applicable apply/patch writes, the handler waits for the exact publication. Committed-but-unapplied/recovery outcomes can return `UNAVAILABLE` with redacted `details.persistedConfig` and an optional new raw token. Publication/rollback failure is a different outcome and does not supply that persistence receipt. Preserve these distinctions; do not translate every error into “nothing saved.” [Application handling](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/config.ts#L567-L668), [post-commit failure handling](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/config.ts#L691-L736).

Restart-required changes do not use that hot-application wait. A successful response can contain `sentinel.payload.stats.requiresRestart: true`; the optional `restart` receipt and persisted sentinel are scheduling evidence, not a new process or applied-revision proof. In hybrid mode the reload owner can schedule restart without that direct `restart` field. Reconnect to the same installation/generation and reconcile the read tokens and serving identity. [Restart classification](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/config-write-flow.ts#L139-L165), [sentinel/direct scheduling](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/config-write-flow.ts#L234-L315).

A successful unchanged patch returns `noop: true`, `changedPaths: []` before a new application attempt. It cannot establish recovery of an earlier saved-but-unapplied revision. Follow the recorded apply/restart recovery guidance. [No-op branch](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/config.ts#L1005-L1027), [recovery contract](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/docs/gateway/configuration/config-rpc.md#L79-L98).

## Reload, lifecycle and readiness

- Supported reload modes are `hybrid` and `off`. `off` continues watching/validating but passive activation waits for restart; earlier `hot`/`restart` modes and configurable reload debounce are retired. Classify paths using the selected runtime/plugin metadata, not a product-maintained static list. Unknown reload paths default to restart; channel/plugin work can defer activation. [Reload contract](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/docs/gateway/configuration/hot-reload.md#L88-L122), [settings resolver](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/config-reload-settings.ts#L1-L10).
- `gateway.suspend.prepare` accepts a request ID, optional `drain` and `terminalPolicy: preserve|terminate`. Results distinguish busy, draining and ready; status uses the returned suspension ID, expiry and optional write custody. This is cooperative process-admission preparation, not suspension of a cloud VM. The coordinator's lease expires after two minutes and attempts to reopen admission/scheduling. Missing custody facts remain unknown. [Wire contract](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/packages/gateway-protocol/src/schema/gateway-suspend.ts#L6-L156), [lease owner](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/infra/gateway-suspend-coordinator.ts#L24-L28), [expiry recovery](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/infra/gateway-suspend-coordinator.ts#L137-L184).
- Suspend handoff binds `pid` and `processInstanceId` and requires the host lifecycle owner. Targeted stop/restart checks the live lock's `pid`, `ownerId` and `port`. Restart preflight is explicitly not the atomic suspension fence. These process identities supplement Business Claw's durable org/instance/generation binding; they cannot replace it. [Handoff handler](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/suspend.ts#L64-L103), [stop/restart handlers](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/restart.ts#L32-L142).
- The main port multiplexes WS control/RPC and HTTP services. The documented effective container default may bind `0.0.0.0`; do not infer private ingress from a local default or publish that port accidentally. Bind/network policy remains the deployment owner's later work. [Runtime/bind contract](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/docs/gateway/index.md#L71-L127).

| Observation | What it establishes | What it does not establish |
| --- | --- | --- |
| `/health[z]` 200 | HTTP listener liveness | Startup, database/channel admission, applied config, provider success. |
| `/startup[z]` 200 | Startup settlement and no drain | Channel health or full assistant usability. |
| `/ready[z]` 200 / `ready:true` | Upstream readiness policy at observation time | Every optional agent, external credential/model/Notion action, backup or tenant isolation. |
| `coreReady:true` | Core checks excluding channel availability | Full channel readiness; HTTP status still follows overall `ready`. |
| `health` RPC | Health facts, sometimes cached | A universally fresh live probe; `probe:true` requests a refresh and can contact channel services. |

The [probe handler](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-http-probes.ts#L42-L136) uses GET/HEAD, no-store responses and 200/503; unauthenticated remote probes omit detailed subsystem/version information. The [readiness checker](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server/readiness.ts#L96-L219) distinguishes startup/drain, state/agent database failures, plugin replacement and channel policy; channel observations may be cached for one second and some restart/grace states are tolerated. The [health handler](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/src/gateway/server-methods/health.ts#L70-L154) refreshes or serves cached facts. [Health documentation](https://github.com/openclaw/openclaw/blob/8b18b5578f66eab1501cba4cef2310d88bfb9a41/docs/gateway/health.md#L82-L124) describes startup versus readiness, optional-agent behavior and diagnostic disclosure. Do not trigger deep probes or `update.run` as passive source verification.

## Architecture reconciliation and next implementation boundary

No contradiction was found with the architecture's isolated per-org runtime, schema-driven intent, separate persistence/application states or single lifecycle owner. Its old source pin remains historical evidence, not proof that release 10.9 was integrated. The concrete adapter must preserve raw CAS versus source/applied tokens, restart/no-op outcomes, exact array replacement intent, plugin-dependent validation and expiring process leases. Generic HTTP success or an authored observation must never promote Business Claw's full `ready` state.

The next source-only data slice can normalize bounded, redacted adapter observations/receipts bound to the same organization, instance, generation, installation and immutable release. It must not accept complete secret-bearing Gateway config, dispatch an RPC, infer authorization, parse token internals or treat a missing hash as a mismatch. A live transport, authenticated target registry, qualified artifact/schema preflight, lifecycle broker and two-org acceptance remain separately gated. Existing portable v1 confirmations remain proposal data.
