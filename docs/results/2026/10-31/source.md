# Managed control-plane source preparation

31 October 2026 (Europe/Rome).

The owner delegated the product direction with “I approve. You choose.” Root
selected a managed service with an isolated Gateway boundary per customer
organization. [The spec](../../../spec.md) preserves the full hosted outcome;
[the architecture proposal](../../../proposals/managed-service-architecture.md)
pins the inspected upstream contracts. Comparison names and unread external
content were not turned into requirements.

This original repository implements the first control-plane foundation:
strict portable one-org/one-instance generation records; bounded setup intent;
reviewed, confirmed, cancelled and superseded proposed operations; guarded
revisions/generations, terminal retries and unverified observations. The browser
uses the shared domain directly for actual local records, JSON import/export
and explicit device saving. No command dispatches, and no record can set live
readiness. This preview is not a completed managed service or actual tenant
isolation proof.

Review corrected impossible operation revisions, observation timestamps outside
the workspace lifetime, completed-operation retry semantics, the device-save
confirmation gap and invalid-saved-copy recovery. Existing form/workspace data
is preserved on rejected input. The static host's build script only inspects
owned source; it never imports product modules or runs the authored tests.

Static preparation passed Node syntax and TypeScript 5.9.3 AST parsing for
five JavaScript modules, both relative-import targets and all named imports,
14 unique literal domain case names, 68 unique HTML IDs, 55 script ID targets,
13 ARIA/label targets, three local assets, SVG parsing, four JSON files and
UTF-8/whitespace inspection. The source seal is [source.json](source.json).
Local installation/build, product imports and authored case execution are **0**.
No dependency installation or active workflow is introduced.

The [14 domain cases](../../../proposals/domain-checks.md) and
[four browser scenarios](../../../proposals/browser-checks.md) are prepared and
**UNRUN**, requiring their own Business Claw execution approval. Clero's now
closed 72-case scope does not authorize this project's checks. Local Node is
26.8.2; no fresh environment is proposed. The domain controller has pre/post
source guards, a 30-second child-process deadline, bounded output and no file
fixtures. The browser scope uses disposable authored/local data only.

No account, Auth policy, grant, migration, DB, provider/secret binding, customer
runtime, model call, remote MCP consent or paid resource was created. The earlier
local Storage Guard failure is respected; there was no local build/install or
large worktree. This new original source tree is small and has no environment,
dependency tree or copied Git history.

Personal GitHub publication and the static Vercel preview are recorded in a
separate publication receipt after source upload. A static preview deploy
cannot establish actual hosting of Gateway processes. Identity, persistent
control-plane storage, VM/ingress/secrets/backup ownership, schema integration,
real configuration/chat/Notion/memory/self-building and two-org live acceptance
remain unfinished. The complete portfolio goal is not achieved by this source
milestone, and the four non-priority apps received no routine work.
